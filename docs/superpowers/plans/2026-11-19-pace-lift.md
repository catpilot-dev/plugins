# Pace Lift Implementation Plan (rev 2)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Lift the e2e accel ask toward the speed target in proportion to the gap, scaled by personality, in experimental mode.

**Architecture:** A new catpilot planner hook `planner.e2e_accel` passes the e2e ask through the plugin chain (finite-checked, fail-safe pass-through). A new plugin `pace_lift` has a pure law module (`lift.py`: target and gate from one tick's inputs) and a stateful hook module (`hook.py`: params, hard resets, ask cap, lead hold, rate limits, bounds, telemetry).

**Tech Stack:** Python 3.12, numpy, pytest. Catpilot plugin framework (`hooks.run`, `PluginPub`, `config.read_plugin_param`).

**Spec:** `docs/superpowers/specs/2026-11-19-pace-lift-design.md` (rev 2). Requirement numbers below refer to it.

## Global Constraints
- Strength m/s²: aggressive 0.40, standard 0.20, relaxed 0.0, unknown 0.0. Params `PaceLiftAggressive`, `PaceLiftStandard` (clamped 0–0.6), `PaceLiftEnabled` (bool, default true).
- Gap ramp [1.0, 4.0] m/s → [0, 1]; speed fade-in [13.89, 16.67] m/s → [0, 1]; ask cap [−0.10, 0.0] m/s² → [0, 1].
- Hard resets (output = a_e2e that tick, lift = 0): disabled, off, gas, brake, standstill, stop, ask_decel (a_e2e ≤ −0.10), no_model (short or non-finite inputs).
- Soft gates in order: plan_decel (min v over t ≤ 6 s < v_ego − 2.0), curve (max |v × yaw_rate| over t ≤ 6 s ≥ 1.5), lead_gap (dRel < T_FOLLOW·v + 6.0 + 0.5·v; once tripped, clears at ≥ T_FOLLOW·v + 6.0 + 0.8·v), lead_closing (vRel < −0.5; clears at ≥ −0.2), none_needed. All soft gates hold 2.0 s. (V8, chosen by the user 2026-11-19 after the replay tuning; this supersedes the 1.0 m/s margin and 1.0 s lead-only hold in Tasks 2–3, implemented in commit a5e0f3a.)
- T_FOLLOW s: aggressive 1.25, standard 1.45, relaxed 1.75.
- Output = max(a_e2e, min(a_e2e + lift, a_cruise)). Rise ≤ 0.25 m/s³, fall ≤ 1.0 m/s³, dt clamped 0–0.2 s.
- Never touch the BMW plugin, the DCC law/0x194, speedlimitd's target, or the MPC. No push, no deploy. Local commits only, on branch `pace-lift` (from `rebase/v0.11.2`) in each repo, with no `Co-Authored-By`.
- Dev machine has a real writable `/data`: never run install/boot/launch scripts.

## Review Focus
1. Model starts braking mid-lift (a_e2e +0.1 → −0.5 in one tick) → output == a_e2e on that tick (Task 3 `test_ask_decel_same_tick`).
2. Lead cut-in at a short gap mid-lift → gate `lead_gap` that tick, lift falls ≤ 1.0 m/s³, held 1.0 s after it clears (Task 3 `test_lead_cut_in_and_hold`).
3. NaN anywhere (model arrays, lead, a_cruise, hook return) → no lift, planner keeps the pre-hook value (Task 1 `test_hook_nonfinite_passthrough`, Task 2 `test_nonfinite_inputs`).
4. Plugin loaded the device way (by file path, module name `plugins.pace_lift.hook`, no PYTHONPATH help) → hook registers (Task 3 `test_registry_style_load`).
5. Speed target below v_ego, or a_cruise below a_e2e → output == a_e2e exactly (Task 3 `test_cruise_below_ask_passthrough`, Task 2 `test_negative_gap_no_lift`).
